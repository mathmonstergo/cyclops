# Unit 0b UI 布局 Prompt：持久文档解析进度

状态：等待用户将本 Prompt 交给视觉 AI 生成桌面端与移动端布局图；收到并确认布局图前，不实现本单元 React UI。

## 视觉命题

这是一个本地客服知识库管理工具，界面应安静、克制、信息密集且适合重复操作；解析进度像文件状态的一部分自然附着在名称附近，不做仪表盘、营销卡片或装饰性视觉。

## 可直接交给视觉 AI 的 Prompt

请基于一个已经存在的本地知识库管理后台，设计“文档列表 + 文档详情 Drawer”的高保真布局图。不要重新设计整站，不要做营销页，不要增加首页、统计卡片或装饰插画。保留现有左侧导航、顶部工具栏、文档表格和右侧 Drawer 的工具型结构。

目标用户是内部客服知识库运营人员，需要上传 PDF、Word、xlsx、Markdown 等材料，观察后端持久解析任务，审核切片后再生成向量。用户关闭 Drawer、切换页面或关闭浏览器后，解析仍由后端继续；UI 只展示数据库中的同一任务状态。

请同时输出 1440x960 桌面端和 390x844 移动端布局图，至少覆盖以下两个画面：

1. 文档列表正在解析：
   - 保持现有表格列，不新增“进度”列。
   - 文件名单元格中，文件图标、可截断文件名和紧凑进度组件在同一信息组内；进度紧贴文件名右侧，不挤压其他列。
   - 紧凑进度组件包含一条短而细的进度条和百分比，例如 43%；状态文字只在必要时显示“排队中”“提交中”“解析中”“落盘中”“失败”。
   - 行高保持适合批量扫描，不把每行做成卡片。
   - 终态不保留满格进度条：完成后回到普通业务状态“待审核”，失败显示克制的错误状态和重试入口。
   - 表格同时展示若干其他状态样例：待解析、排队中、解析中、待审核、向量待生成、向量可检索、失败可重试。

2. 文档详情 Drawer 正在解析：
   - 沿用现有右侧 Drawer，不在 Drawer 内嵌套卡片。
   - 顶部依次为静态标题区域、文件名/文件类型/当前业务状态；打开后初始焦点落在标题或内容容器，不落在 Copy ID、删除或其他按钮。
   - 解析区显示同一持久任务的阶段、百分比、已处理页数/总页数、任务 ID、最近更新时间和错误详情；推荐使用紧凑的分段步骤或垂直状态列表，而不是大型仪表盘。
   - 阶段固定为：排队 queued、提交 provider submitting、解析/轮询 polling、落盘 finalizing、完成 completed、失败 failed。
   - 任务进行中时，关闭 Drawer 的提示只表达“任务将在后台继续”，不要出现教程式说明或显眼横幅。
   - 失败状态提供明确错误摘要和“重试解析”主操作；完成后解析区收起为简洁摘要，并突出后续“审核切片”或“生成向量”操作。
   - Copy ID 等图标按钮保留 Tooltip：鼠标首次悬停 500ms 后出现；在 400ms warm-up 内移动到相邻图标可立即显示；键盘 focus 仍立即显示。

交互与层级要求：

- 主工作区优先，使用现有设计 token、字体、边框和状态色；只用一个主要操作色，错误色仅用于失败。
- 不使用渐变背景、玻璃拟态、悬浮装饰、圆形大图标、卡片矩阵或大面积品牌色。
- 卡片圆角不超过 8px；进度条和按钮尺寸稳定，状态文字变化不得造成表格列宽或 Drawer 布局跳动。
- 桌面端表格保持高信息密度；移动端改为可扫描的文件行布局，但仍不要把每条记录做成装饰性大卡片。
- 文件名很长时必须可靠截断，进度百分比与操作按钮不可重叠。
- 需要画出 loading、empty、failed、processing、completed 的主要状态差异，但不要在同一个画面堆满所有解释文字。
- 所有按钮使用熟悉图标或图标加短文字；Copy、关闭、重试等使用 Lucide 风格图标并保留可访问名称。

请把最终图的设计重点放在三件事：列表中一眼看到哪些文件仍在后台解析；打开 Drawer 后能理解当前阶段与真实进度；关闭 Drawer 或切换页面不会给人“任务会停止”的误解。

## 内容计划

- 主工作区：现有文档表格，文件名旁展示紧凑持久任务进度。
- 次级上下文：右侧 Drawer 展示同一任务的完整阶段、页数、百分比与错误。
- 后续动作：完成后进入切片审核/向量生成，失败后可创建新的解析任务。

## 交互命题

- 行内进度只做平滑宽度变化，不闪烁、不改变行高。
- Drawer 沿用现有进入/退出动画，打开时把程序化焦点放在静态标题区域。
- Tooltip 采用 500ms 首次延迟与 400ms 相邻 warm-up，键盘焦点即时显示。
